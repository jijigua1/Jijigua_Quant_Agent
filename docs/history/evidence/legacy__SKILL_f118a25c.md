# data_research

## 什么时候用

- 第一次接触一份行情、因子、股票池或状态数据时。
- 数据版本更新，或者研究结果异常、需要排查数据原因时。
- 要用分钟数据构造日频行情或执行价格之前，先检查分钟数据合同。

**不适用：** 判断因子是否有效（用 factor_research），评估策略收益（用 strategy_backtest）。

## 需要的输入

- 已登记到数据目录的引用 `data:<name>`。不接受文件路径，因为数据只能由宿主登记。
- `observed_at`：数据在一天中何时可以看到。例如收盘价是 `close T`，开盘价是 `open T`，收盘后才发布的因子写作 `after close T + lag`。
- 可选：交易日历 `data:<calendar>`，用来发现缺失的交易日。
- 分钟数据还需要**完整声明的合同**：时间戳是区间开始还是结束、成交量单位、成交额单位、开盘和收盘集合竞价的表示方式。

## 工具

| 工具 | 用途 |
|---|---|
| `data.profile_panel` | 面板的形状、日期范围、类型、缺失率、全空列、inf、非正价格、重复或乱序日期、与交易日历的差异，以及声明的观察时点 |
| `data.minute_quality` | 按合同标准化分钟数据并聚合成日频，汇总质量问题和每日状态（停牌、无数据、无成交、截断、覆盖不足、正常） |

## 工作流程

1. 对每一份输入调用 `data.profile_panel`，并带上交易日历。
2. 写下时间语义：每份数据在 T 日什么时候可以观察、信号什么时候产生、订单在哪个交易日的什么时段执行。可观察时间晚于执行时间的数据，不能用于这次交易决策。
3. 分钟数据先调用 `data.minute_quality`。在 `status_counts` 中，只有 `ok` 的交易日能作为完整的日频行情。
4. 把发现的问题交给下游 Skill，不要自己修改数据。

## 怎样解释结果

- `status = fail`：价格非正、出现 inf、日期重复或乱序、日期不在交易日历上。**停止**，先修复数据，不进入研究。
- `status = warn`：缺失率高或交易日历有缺口。可以继续，但报告里必须写明。
- 缺失值是"未知"，不是 0；停牌、无成交、缺数据是三种不同的情况。
- 只看分钟数据无法判断停牌，需要单独的停牌数据。

## 停止和拒绝结论的条件

- 数据没有登记（`DATA_NOT_REGISTERED`），或者登记了但内容为空（`DATA_MISSING`）。
- 分钟合同没有声明完整（`CONTRACT_INCOMPLETE`）。不能猜测时间戳约定或单位。
- 价格单位、复权状态或数据来源不明，却要用于真实股数回测。

## 错误处理

所有错误都以 `{"ok": false, "error": {"code", "message"}}` 返回，并写入审计日志。不要通过换一个路径或换一个工具来绕过错误；把错误原样写进报告的"失败实验与异常"一节。

## 与其他 Skill 组合

本 Skill 输出的 `ref`（`data_profile` 产物）供 research_reporting 填写"数据来源和时间范围"一节；`daily_ref` 可以由宿主重新登记为日频面板，供其他 Skill 使用。
