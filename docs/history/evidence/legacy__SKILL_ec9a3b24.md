# strategy_backtest

## 什么时候用

- factor_research 已经在冻结参数下得到结果，需要估计"按规则交易时，账户会怎样"。
- 交叉验证另一个回测引擎时，用同一份订单在两边各跑一遍。

**不适用：** 判断因子是否有预测性；用回测结果反过来挑选因子方向、持有期或执行窗口。

## 需要的输入

- `score`：T 日收盘后的信号面板（因子或模型分数）。
- 订单规则：`direction`、`top_n`、`holding_days`、回测起止日期、`value_per_name`。这些都属于冻结参数。
- 执行价格面板 `open` 和估值价格面板 `close`，必须是**未复权**价格，因为账本按真实股数记账。
- `initial_cash`、`costs`（佣金率、最低佣金、印花税率、滑点），可选停牌面板 `suspended`。
- `engine`：引擎名称。默认 `qrtk_reference`，宿主可以注册其他引擎。

## 时间语义

```text
T 日收盘：score[T] 可观察 -> 生成订单（signal_date = T）
T+1 开盘：订单执行（卖单优先）；停牌、缺价、涨跌停、T+1 规则导致的拒单都会记录下来
T+1 收盘：按收盘价估值；成交价和估值价是两个输入
每隔 holding_days 个交易日调仓一次，持仓不重叠
```

## 工具

| 工具 | 用途 |
|---|---|
| `strategy.signal_to_orders` | Top-N 不重叠调仓：退出名单的股票生成卖单，新进入的股票生成按金额的买单。持仓按"打算持有"来跟踪，所以被拒的买单之后会以 `no_position` 拒单的形式显示出来 |
| `strategy.backtest` | 把订单交给指定引擎。返回绩效、对账结果、拒单分类、账本假设，以及每日账户产物 |

## 工作流程

1. 确认 spec 已冻结，回测区间是**测试段或之后的区间**。在研究段上回测，只能当作诊断用途。
2. 调用 `strategy.signal_to_orders`。
3. 调用 `strategy.backtest`。对账不通过时，工具直接报错，不会返回结果。
4. 结果连同 `assumptions`、拒单统计和引擎名称一起交给 research_reporting。

## 怎样解释结果

- 这里的收益是"模拟账户在所列假设下的可交易收益估计"，不是实盘收益。
- 拒单分为两类：`data_unavailable`（数据缺失）和 `not_executable`（停牌、涨跌停、T+1 等原因无法成交），需要分别说明。
- Sharpe 和年化收益在样本很短时意义很小，应该同时报告交易日数。
- 参考账本不建模冲击成本、订单簿、公司行动和退市清算。

## 停止和拒绝结论的条件

- 引擎没有注册（`ENGINE_UNAVAILABLE`）：不要悄悄换成另一个引擎。
- 账本对账失败（`RECONCILE_FAILED`），或者没有任何成交（`INSUFFICIENT_EVIDENCE`）：不给出收益结论。
- 输入了复权价格，或者价格中有 inf、非正值、日期缺失：直接报 `TOOL_FAILED`。

## 错误处理

所有错误都写入审计日志和报告。不允许在报告里用理论分组收益替代缺失的账户收益。

## 与其他 Skill 组合

`orders_ref` 和 `ref` 是不可变的产物。不同引擎可以用同一份 `orders_ref` 运行，结果放进各自的产物，互不覆盖。
