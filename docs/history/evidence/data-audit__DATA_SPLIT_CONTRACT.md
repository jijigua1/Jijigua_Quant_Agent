# Phase 3-A Train / Validation / Holdout 合同

机器合同：`../schemas/data_split_contract.v1.json`（原内部附件未公开），版本 `qra-split/1.0.0`。边界以 Asia/Shanghai 日期、含端点、交易日历为准；自然年端点并不保证是交易日。现有静态元数据按年合计：Train 2020–2023 为 970 个观测交易日，Validation 2024–2025 为 485 日，Holdout 2026-01-01—2026-10-09 为 183 日。**这些是覆盖计数，不是已认证独立样本外表现。**

三个分区在机器合同中分别具有独立的 `id`、`version`、日期与访问声明，变更任何边界或访问级别都必须发布新合同版本并重新验收。

| 分区 | 日期合同 | 研究侧访问 | 数据/标签规则 |
|---|---|---|---|
| Train | 2020-01-01—2023-12-31 | **尚未发布独立快照，接口拒绝读取**；未来只允许固定哈希的六个原始字段 | 发布后可探索/调参；标签执行与持有期必须在 Train 内成熟 |
| Validation | 2024-01-01—2025-12-31 | **尚未发布独立快照，接口拒绝读取** | 发布后用于已选假设验收；看到结果再调参须记录为已使用验证集 |
| Final Holdout | 2026-01-01—认证截止 2026-10-09 | **研究 API 一律拒绝**；本阶段无评估入口 | 不发布目标收益、IC、组合指标、缓存或完整区间性能摘要；未来只由独立评估器在明确授权/次数约束下使用 |

`SplitReader` 是本阶段的**离线接口原型**：可信调用者固定角色 `research_agent`；分区边界、六字段硬白名单和 **v2 降级清单**的规范化 SHA-256 均须匹配版本化合同。旧 `ControlledReader` 会先把整个 PKL 文件读入内存，再按日期切片，所以不能直接用含 2026 数据的宽表给 Train/Validation 读。交付的机器合同将两者标为 `NOT_PUBLISHED`，请求返回 `SPLIT_RESOURCE_NOT_PUBLISHED`；只有未来单独发布且经轴/哈希审核的分区资源，才可开通探索性读取。`holdout` 请求返回 `HOLDOUT_NOT_PUBLISHED`；未来字段/状态字段不在六字段白名单。成功和拒绝均向审计回调写入角色、分区、字段、日期、结果，不写数值。旧 v1 的 `RESEARCH_READY` 仅作为历史记录；已发布分区的输出仍只标 `PROFILED_EXPLORATORY_ONLY`。

**标签成熟与分区边缘。** 因子 T 收盘取值的最早决策时点为 T 收盘后；若执行延迟为 `L≥1` 个交易日、持有 `H≥1` 个开盘区间、embargo 为 `E≥0` 个交易日，则信号所在日索引 `i` 仅在 `i+L+H+E < 分区交易日数` 时可生成该分区内标签。历史暖机须只读该分区或更早可用的原始输入，禁止读取后续分区标签；训练尾端与验证尾端分别 purge，重叠收益标签需另做 serial-dependence 处理。`eligible_signal_dates` 对边界及参数做合成测试；具体因子回看窗口、交易时点和未来标签构造仍须在 Phase 3-C 的受控评估器中逐项验证。

**真实隔离状态：未完成。** 这只是在独立 `phase3a_data` 中实现的接口和 Schema，未注册进冻结的 v0.6.8 Agent；同一 Linux 身份若仍能直接访问原始整段 PKL，绕开 Python 包即可看 2026 数据。故目前**不能声称系统级、进程级或所有路径上的 Holdout 隔离**。上线前至少要发布分区只读快照/独立资源 ID，仅向研究身份提供 Train/Validation 文件或行级服务；Holdout 源文件只对独立评估身份可读，评估器记录授权、次数、输入版本及不泄露逐日表现的结果。其它已注册资源、缓存、日志、报告和结果导出也要作旁路清查。未经这些验证，2026 数据不得加入 Agent 工具白名单。
