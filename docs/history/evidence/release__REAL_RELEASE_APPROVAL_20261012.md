## 执行与失败处理

1. 执行前重核六源文件 SHA/大小、候选 CSV SHA、代码 SHA、文件身份和发布空目录，检查没有并发更新；先对获批的固定批次再做一次 `dry_run=True`。任一不同即中止，不换用新版本自动重试。
2. 用同一受审入口依次发布 Train、Validation；每份输出使用临时目录、写入六个数值文件与 manifest 后原子改名。每份输出记录六源指纹、候选上市表与代码指纹、屏蔽/排除计数、真实日期/代码轴、状态和文件哈希。
3. 两份完成后独立重算 manifest/文件 SHA；以 `quantagent` 只读验证分区日期/截面及原始、私有和 Holdout 权限拒绝。仅当两份都通过才可宣布数据已发布。**不**在此轮注册主 Agent、不运行回测或 2026 评估。
4. 失败时临时未提交目录由受审程序清理；如果 Train 已提交而 Validation 失败，已提交目录保留并标记整批未完成，不对 Agent 注册，也不擅自删除历史产物。另行审查后再决定精确清理。
