# Phase 1-D 历史接入计划

本文件保留2026-10-11离线阶段的原始建议；其中“尚未使用真实 API/SSH、等待账号”等状态已被后续实施替代。2026-10-12 当前进展见 [Phase 1-E 报告](legacy__REPORT_5062196a.md)，下一批工作见 [集成入口](legacy__INTEGRATION_46042f7f.md)。下文不代表当前部署状态。

日期：2026-10-11。遵循最新 Development First, Production Hardening Later 策略。以下均为 **待验收后的实施建议**；本轮未使用真实 Key、SSH 或共享数据。

## 1. 先接真实 DeepSeek，不依赖服务器 Runner

先在本地以真实模型调用已经审阅的两个 Mock Tools，验证自然语言理解、工具选择与反馈修正。无需 CPU VM，无需先建设生产沙箱。

| 具体开发任务 | 建议修改文件 | 验收 |
|---|---|---|
| 增加操作者选择的 `development` Provider 装配配置 | `app.py`、`resources/agent.toml`、`cli.py` | 无配置时仍保持离线；模型无法启用传输或切换凭据 |
| 明确启用固定端点 HTTPTransport，校验账号实际可用模型 | `providers/deepseek.py`、Provider 测试 | 真实原生 Tool Calling、JSON 本地校验、回填 Tool ID 成功；所需能力不足则拒绝 |
| Key 仅经已允许引用交给 Adapter | `llm.py` 的 SecretStore、启动配置 | 不写入参数、Skill、提示词、实验账本或日志；Mock 保持零凭据要求 |
| CLI 连续对话与上下文预算 | `cli.py`、`workflow.py`、`store.py` | 先单任务对话，保留 task_id；避免跨任务混淆授权；长上下文可控 |
| 真实调用预算、退避及中断回归 | `llm.py`、`workflow.py`、测试 | 失败不执行工具；限额下停止；Key canary 和拒绝测试继续通过 |

初始每任务最多 4 轮计划、8 次模型尝试、6 次 Tool 尝试，单次输出至多 1,024 tokens、请求超时 20 秒、至多 1 次重试。重试包含在总调用上限。最多 1 个任务并发，先手工启动。最多理论请求输出 8,192 tokens；这是输出上限，不含输入消耗，实际费用需按账号模型和返回 usage 验证。后续增加累计 token/费用上限；不能把未知 usage 当零。

真实验收任务仍使用固定模拟数据：模型查询数据、解释指标假设、选择 3 与 5 两个窗口、比较返回数值并明确模拟结论。不得要求真实模型输出逐字等同于 Mock；验收 Tool 合法性、证据引用、停止行为和关键数值。离线回归与真实冒烟分开报告。

当前 Adapter 依据官方 [Tool Calling](https://api-docs.deepseek.com/guides/tool_calls/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 与 [Chat Completion API](https://api-docs.deepseek.com/api/create-chat-completion/) 编写。普通 JSON 模式不是服务端严格 Schema；本地验证必须保留。当前未启用 beta strict 模式。官方文档及账号可用模型应在接入时重新核对；配置里存在模型名称不证明账号能用。

本轮 SSE 合同已处理消息分片、Tool 参数分片、完成标志与用量。为避免秘密跨片泄漏，标准化事件在完整响应校验和脱敏后才发布；目前不是实时逐字 CLI。真正用户流式交互另行开发和验收。

## 2. 确认服务器开发边界后再部署

CLI、Agent、固定受审 Tool 与任务账本可以先在现有 GPUShare 的明确授权非 root 开发身份下运行。仍不能把 root SSH 管理账号交给 Agent。没有合适身份时，提交具体账号需求，由用户/管理员单独批准；本轮没有创建账号。

建议未来变更范围仅包括：

```text
/opt/jijigua-quant-agent/research_agent/
├── src/、resources/、tests/、docs/、pyproject.toml
├── .venv/                      本项目 Python 环境
└── var/
    ├── state/                  SQLite 与任务检查点
    ├── logs/                   脱敏开发日志
    └── runs/<task_id>/         本项目实验与报告
```

软件包实际资源仍位于 `src/research_agent/resources/`；安装后的运行配置需要显式指向受控配置目录，不依赖编辑 `site-packages`。凭据不放在上述代码、运行产物或数据发布目录中；由启动者通过独立受保护配置注入 Adapter，研究子进程清空环境，仅保留必需白名单变量。

大型输出位置、日志保留策略和可写磁盘余量在部署前检查，不能自动扩展到其他研究员目录。旧 Agent 同级保留，不移动或覆盖它；不修改 `/srv/project-owner/` 其他项目。

开发用独立目录、非 root、venv、固定 Tool、低并发及超时是基本保护，**不是正式安全沙箱**。它们适用于受审固定程序；不能据此执行任意模型生成代码或未知第三方程序。

## 3. 数据和研究程序合同

优先接入一份资产所有者确认并发布的 CSV/Parquet 小切片。Agent 使用逻辑 `resource_id`，由可信资源目录解析到已批准只读文件；不接受模型传入自由路径。发布资源可以位于独立只读目录，Agent 工作区只保存清单和内容指纹。

| 合同 / 接口 | 必须包含 | 实现边界 |
|---|---|---|
| ResourceManifest | 来源、许可/所有者、证券范围、日期范围、频率、时区、复权、可获得时间、Schema、内容 SHA-256 | 缺失时间/复权口径先拒绝进入真实因子/回测 |
| `list_resources` / `describe_resource` | 脱敏元数据和资源能力 | 只列明确授权资产，不扫描其他研究人员目录 |
| `read_data_slice` | resource_id、字段、证券、起止、行数/字节上限 | 只读、封闭参数、日期/行数/字节限制；链接/路径校验与内容指纹 |
| `factor_evaluate` | 固定受审因子实现 ID、参数、输入指纹、结果 Schema | 初版不运行模型生成代码；计算、对齐和统计由确定性程序实现 |
| `research_job` / RunnerClient | job_id、授权引用、版本、输入资源、输出范围、预算、取消/状态协议 | 先固定类型作业；默认禁止任意命令、导入路径、网络和凭据传递 |
| ExperimentRecord | 假设/修改理由、数据/代码/环境版本、样本划分、统计结果、失败类型 | 回测失败和程序失败分开；结果验收后才写为有效证据 |

不复制 88 GiB 因子矩阵；按证券、字段与日期发布小切片。涉及私有 pickle，必须由资产所有者提供来源可信、经审查的转换流程或直接发布安全格式，不能由 Agent 自行加载。不因开发策略变化自动批准 pickle 转换。

已有 Pyx 或回测代码仅在完成来源、最小依赖、交易时间、复权、未来数据、收益/成本口径审查后接入适配器。没有证据证明可靠时，不以它作为第一轮回测基准。优先复用合格底层实现，不复用旧 Step1–Step9 固定架构。

## 4. 首个真实实验的保守配置

建议先做数据质量与单因子评价，暂不涉及交易。初始切片不超过 20 只证券、120 个交易日；实际行数还需按频率显式限制，初版以日频为宜。固定计算程序，单任务/单并发、CPU 1 核目标、内存 512 MiB 目标、运行超时 60 秒、输出不超过 10 MiB。

这些是开发任务准入和监控目标。没有 OS 配额时，不能称为 CPU/内存/磁盘硬限制；只选择已测量且能在预算内运行的固定 Tool。超时需记录实际终止情况，程序不得自行产生后台子进程。资源异常立即停止继续提交任务，由操作者处理，不能给模型开放 `kill` 等系统维护工具。

验收：可获得时间和标签成熟约束明确、无静默填零/未来数据、固定输入得到可复现指标、独立目录保留清单/代码版本/配置/报告、原始输入指纹一致。真实回测需另加交易规则和收益口径基准测试，不能由数据读取成功推导出回测正确。

## 5. 后续顺序

| 阶段 | 实际新增能力 | 前置条件 |
|---|---|---|
| 1-E：真实模型 | 自然语言研究目标到真实 Tool Calling | 当前核心验收、独立 Key、调用预算 |
| 1-F：服务器开发接入 | 非 root CLI + 小切片 + 固定研究 Tool | 用户确认部署范围、身份、数据发布和 Tool 实现 |
| 2：专业 Skills | 数据质量、因子评价、结果诊断 | 真实资源合同和确定性指标基准 |
| 3：自主闭环与记忆 | 有假设的多轮实验、跨任务证据检索 | 证据验收、预算、停止/失败规则 |
| 4：后台研究 | Worker、租约、取消、重启恢复、保留策略 | 幂等/结果提交协议、受控固定作业环境 |
| 5：生产加固 | 独立身份、正式沙箱、整树硬限、防篡改审计 | 平台/管理员确认执行机制后专项验收 |

不要求现在购买 CPU VM。正式长期自主运行前必须完成加固；平台机制不足时再比较独立执行实例。交易与生产维护接口持续隔离，不因完成开发研究闭环而开放。
