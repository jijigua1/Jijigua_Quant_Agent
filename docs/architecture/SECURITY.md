# 安全架构、信任与权限

## 信任分层

| 主体 | 可做什么 | 不应得到什么 |
|---|---|---|
| LLM/论文 | 提出主张、计划、封闭参数 | 任意路径、Shell、直接授权、签名密钥 |
| 普通Agent | 读授权Train/Validation、计算、保存自身成果 | 原始完整PKL、私有Test、独立账本写权限 |
| 发布身份 | 对固定只读FD静态解码并生成staging | 任意root文件重新打开能力 |
| root broker | 校验请求、固定源、权限、回执登记 | 不应以root执行模型生成候选 |
| 独立评估身份 | 读已批准快照、执行可信算法、签发受控结果 | 主Agent可修改的算法或策略搜索入口 |
| 操作者 | 配置资源与预算、批准定义/代码/数据操作 | 不应把普通聊天同意当无限授权 |

Schema、Skill、Policy和操作者批准是不同检查。`additionalProperties=false`及资源ID限制不能被模型文本绕过。模型内容和Tool结果都是数据，不是可执行指令。密码和Key只由隐藏输入或用户环境注入；HTTP跳转被拒，避免Authorization转发。

## PKL与文件

未知pickle可能执行代码。主Agent不能对上传的任意PKL调用反序列化。静态解码器仅允许已审结构与有限opcode，拒绝未知对象；OS降权、FD白名单和资源限制仍不可省略。自产因子读回仅在固定写入器的已知字节与预期完全一致时允许。链接、任意绝对路径和路径穿越必须拒绝。

## 可信代码不等于沙箱

`paper_agent.registry.TrustedRegistry._load_module`在人工批准SHA后使用Python执行机制加载源码，并拒绝root。此路径拥有Agent的OS权限，**不是恶意代码安全容器**。独立Test可信IR执行器采用受审闭合运算，不应将Registry中任意已批准代码自动加入Test白名单。公开部署在共享或敌对环境前仍需进程隔离、系统调用与权限审查。

## 不可变性与局限

定义、算法语义、数据版本和回执必须绑定指纹。HMAC钥不交给模型，但持钥组件可签名，签名不是数值真值。哈希链在独立权限保护下才能提供更强防篡改；同一可写账号控制代码和账本时不能声称不可删除。缓存须覆盖会影响数值的合同/IR版本；实现语义升级不能悄悄复用旧结果。

## 公开副本

只保留项目代码、合成数据生成器和脱敏工程证据。排除真实行情、2026私有文件、Keys、FD/连接信息、数据库、论文全文、私聊及内部运行日志。全局Skills/MCP/插件属于用户配置，不复制。本项目没有证据表明必须公开任何私人MCP连接才能运行。

`tools/release_audit.py`只输出发现位置，不输出匹配秘密。扫描代码、文档、产物和准备公开的全部Git提交；模式扫描不是无泄露的数学证明，仍需来源、二进制及人工审阅。发现秘密时停止发布，不能靠.gitignore掩盖已经入历史的值。
