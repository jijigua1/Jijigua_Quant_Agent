# Linux与服务器部署边界

## 普通用户离线环境

普通用户按README创建venv即可运行Mock、合成因子和pytest，不需要root。中文图需本机可用CJK字体。`deploy/`不是通用一键生产安装器：模板仍包含内部布局假设，只做脱敏，不声称适合任意机器直接执行。

## 管理员必须先准备的合同

1. 代码目录由管理员控制，研究身份不可写；独立venv与依赖清单、wheel和源码SHA可回滚。
2. Agent、发布、独立评估是不同最小权限身份；仅管理员broker持有固定FD/签名配置。
3. 用户合法行情发布为不可变Train/Validation，研究账号不能读原始跨期PKL或私有Test。
4. 工作区、staging、回执、审计、缓存各自权限明确，拒绝符号/硬链接绕过。
5. 官方Provider秘密输入与非root运行，启动前清理非必要环境，不把Key放argv。
6. 定义冻结、测试许可、次数与曝光台账先就绪，再授权真实Test；回顾性不称盲测。
7. 日更源及盘符是部署配置；不运行本仓库自带任何未知行情采集脚本。

## 启动链与回滚

`deploy/quant-agent`→`launcher_v1.py`→非root Agent子进程与受控broker父进程。`configure_v1.py`、install/enable/rollback脚本涉及系统写入，必须先逐条审阅。源码脱敏后路径与原部署不同，哈希和历史回执白名单需要新环境重新批准，不得复用内部签名材料。

备份代码、配置、wheel、入口和数据库schema证据；只在批准范围替换。回滚Agent不应停掉无关行情cron；历史脚本曾默认操作cron，应优先拆分或使用经审核的保留日更方案。不要因“回滚成功”破坏数据生产任务。

## 验收

先离线pytest和合成数值，再独立Linux身份/FD/ACL拒绝验证；最后才是用户明确授权的真实API及数据测试。检查status/result/logs、PKL、报告版本、标签成熟、预算与错误分类。公共CI不创建root账户、不读取真实Test。

服务器可用磁盘与inode、`/tmp`、成果盘、日志增长应先测；大测试临时目录放独立可控空间。不得擅自清理其他人的目录。临时盘成果须有用户管理的备份；本仓库不自动向外部平台上传。
